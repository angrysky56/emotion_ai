<objective>
Establish SQLite as Aura's one durable truth owner for complete turns and provenance-bound memory.

Purpose: Remove half-turns, duplicate retries, mutable source history, orphan derivations, and ambient storage ownership before any retrieval or lifecycle work can build on them.
Output: Typed contracts, explicit connection/schema ownership, an atomic repository, and deterministic failure-injection tests.
</objective>

## Artifacts this plan produces

- An import-safe `aura_backend.storage` ledger surface with no database/model initialization at import time.
- A monotonically versioned SQLite schema using foreign keys, WAL, finite busy bounds, external-content FTS5, and explicit rebuild support.
- Atomic turn, idempotency, provenance, supersession, retraction, profile, and history contracts.
- Isolated two-scope/fault-injection fixtures under the root deterministic test tree.

## Trust Boundaries

| Boundary | Description |
|---|---|
| API/service command → SQLite | Caller-controlled content, IDs, hashes, and scope enter the sole durable store. |
| Derived-memory proposal → evidence ledger | Lossy inference must not become unsourced or immutable truth. |
| Repository error → logs/evidence | Personal content must not escape through diagnostics. |

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|---|---|---|---|---|
| T-03-01-01 | Tampering / Repudiation | turn transaction | mitigate | Unique scoped idempotency, canonical hashes, BEGIN IMMEDIATE, stepwise fault injection, exact rollback/count assertions. |
| T-03-01-02 | Information Disclosure / Elevation | scope and provenance | mitigate | Mandatory scope arguments, same-scope foreign keys/validation, two-scope adversarial tests. |
| T-03-01-03 | Tampering | supersession graph | mitigate | Immutable sources, explicit edges, self/cycle/cross-scope rejection in one transaction. |
| T-03-01-04 | Information Disclosure | logs and exceptions | mitigate | Fixed codes plus IDs/counts only; captured-log sentinel tests. |

</threat_model>
