Create the read-only preservation inventory and its privacy contract, implementing D-02 and D-03 without touching or migrating any stored data.

Purpose: Establish a content-safe account of Aura's scattered persistence roots before any backup, cleanup, or refactor can claim safety.
Output: A typed inventory library, an explicit CLI, and deterministic privacy/symlink tests.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Personal data roots → preservation CLI | Sensitive local files cross into evidence generation. |
| Filesystem entry → walker | Symlinks and special files are untrusted traversal inputs. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-01-CL | Information Disclosure | public manifest serializer | mitigate | Allowlist public fields and run sentinel privacy tests; keep detailed evidence under `/backup`. |
| T-01-SM | Tampering | source inventory traversal | mitigate | Use read-only SQLite URIs, `lstat`, streaming reads only, and before/after file metadata checks. |
| T-01-PE | Tampering / Information Disclosure | symlink and special-file handling | mitigate | Never follow symlinks; block non-regular files and unstable paths. |
| T-01-FB | Repudiation | overall manifest status | mitigate | Explicit per-check statuses; zero exit only when all required checks ran and passed. |
| T-01-SC | Tampering | package supply chain | mitigate | Add no dependency and do not change the lock; any unexpected install requires the package-legitimacy human gate. |
</threat_model>
