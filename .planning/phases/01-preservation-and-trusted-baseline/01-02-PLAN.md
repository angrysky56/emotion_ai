## Normative preservation CLI contract

All real operations in Plans 01-08 through 01-10 invoke `uv run python -m aura_backend.preservation.cli <subcommand>` from the repository root. Paths passed as repository inputs are resolved beneath `--repository-root`; paths beneath `--backup-root` are required to remain on the allowed outside-Git root. Every JSON artifact uses schema version `1` and the common fields `schema_version`, `command`, `run_id`, `status`, `source_set_sha256`, `checks`, `created_at_utc`, and `tool_commit`. Each `checks` entry has `name`, `status`, and an opaque `evidence_sha256`; permitted statuses are `pass`, `fail`, `blocked`, `not_run`, and `not_applicable`.

### Commands and outputs

| Subcommand | Required options / inputs | Created output |
|---|---|---|
| `inventory` | `--repository-root PATH`, `--backup-root PATH`, `--run-id ID`, `--private-manifest PATH`, `--public-summary PATH`, repeatable `--root ROLE=PATH`, and repeatable `--require-role ROLE` | The exact new `--private-manifest` plus the exact new/atomically replaced `--public-summary`. The public file adds `root_roles`, aggregate counts/hashes, `private_artifact_relpath`, and `private_artifact_sha256`; the private file holds per-file evidence and the random HMAC key. Existing private output is never overwritten. |
| `validate-summary` | `--summary PATH` and repeatable `--require-role ROLE` | No output mutation; validates public-field allowlist, required roles, and required-check status. |
| `preflight` | `--inventory-summary PATH`, `--backup-root PATH`, `--public-summary PATH`, `--ticket-ttl-seconds INT` | A new `<backup-root>/<run_id>/quiescence.<ticket_id>.private.json` plus the exact public summary. Re-runs retain prior private tickets and atomically advance the public pointer. The private ticket records `ticket_id`, `issued_at_utc`, `expires_at_utc`, destination, inventory artifact digest, source-set digest, mount/free-space result, process scan, and per-root open-handle result. |
| `validate-quiescence` | `--summary PATH`, `--inventory PATH`; optional `--require-pass` | No output mutation; validates public schema and inventory/source-set/ticket binding. `--require-pass` also requires an unexpired passing ticket. |
| `backup-from-ticket` | `--inventory-summary PATH`, `--quiescence-summary PATH`, `--backup-root PATH`, `--destination-name NAME` | `<backup-root>/<run_id>/<NAME>.partial` during copy, atomically renamed to `<NAME>` only after parity, plus `<backup-root>/<run_id>/backup.private.json`. The private result records inventory/ticket digests, source-before/source-after/destination hashes, copied roots, and final destination. |
| `verify` | `--inventory-summary PATH`, `--quiescence-summary PATH`, `--backup-root PATH`, `--restore-parent PATH`, `--public-summary PATH` | A unique disposable child of `--restore-parent`, opened by Chroma only after the durable backup is copied into it; `<backup-root>/<run_id>/restore.private.json`; and the exact public restore summary. The disposable child is removed after evidence is finalized. |
| `validate-restore-summary` | `--summary PATH`, `--inventory PATH`, `--quiescence PATH`, and the gates `--require-pass`, `--require-source-unchanged`, `--require-fk-parity`, `--require-retrieval-parity` | No output mutation; validates all upstream digests, required check states, privacy schema, and the named parity gates. |

### Ticket binding and exit status

The inventory public summary carries a backup-root-relative private-manifest locator and digest. The quiescence public summary carries the inventory summary digest, `source_set_sha256`, current private-ticket locator/digest, `ticket_id`, `issued_at_utc`, `expires_at_utc`, and proposed destination. `backup-from-ticket` re-hashes both referenced private artifacts and refuses a missing, expired, non-passing, source-set-mismatched, inventory-mismatched, destination-mismatched, open-handle, free-space, or path-disjointness condition before copying. `verify` binds its result to the inventory digest, quiescence ticket digest, backup result digest, source-set digest, and finalized backup path. A public restore `pass` therefore identifies one exact inventory → ticket → backup → disposable-restore chain.

All subcommands use stable process exits: `0` only when every required check for that command ran and passed; `2` for invalid CLI arguments or input schema; `3` for a blocked safety/precondition state such as stale ticket, open handle, inadequate space, existing/overlapping destination, or missing required evidence; `4` for hash, integrity, FK, count, retrieval, privacy, or other verification mismatch; and `5` for unexpected I/O/tool/runtime failure. When safe, nonzero operations still write a status artifact for diagnosis. `not_run`, `blocked`, partial collection, or resource failure can never accompany exit `0`.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Source roots → backup engine | Irreplaceable user data must remain immutable. |
| Durable backup → disposable restore | Validation may use stateful database clients only after this boundary. |
| Operator ticket → copy command | Human quiescence evidence is untrusted until revalidated. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-01-SM | Tampering / Denial of Service | backup copy | mitigate | Pairwise-disjoint paths, new destinations, before/after source hashes, no deletion APIs. |
| T-01-PE | Tampering | path resolution and copy | mitigate | Allowed backup root, symlink-component rejection, `lstat`, no-follow copy. |
| T-01-FB | Repudiation / Tampering | restore summary | mitigate | Required-check state machine plus hash, SQLite, FK, Chroma count, and retrieval evidence. |
| T-01-CL | Information Disclosure | retrieval evidence | mitigate | Private salt and opaque fingerprints; no document, metadata, collection-name, or raw-ID output. |
| T-01-SC | Tampering | package supply chain | mitigate | Use installed stdlib/Chroma/pytest only; no package or lock changes. |
</threat_model>
